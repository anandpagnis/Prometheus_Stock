## 2026-09-03

### Removed `HttpClient.Timeout` from the Yahoo resilience registration

`MarketDataServiceCollectionExtensions.cs` originally set
`httpClient.Timeout = options.RequestTimeout` inside the `AddHttpClient` configure
lambda. Removed it (committed in `a92de9e`).

**Reasoning:** the registration also calls `AddStandardResilienceHandler()`, which
installs a total-request-timeout strategy (default 30s) wrapping a per-attempt timeout
(default 10s) around the retry loop. A `HttpClient.Timeout` sits *outside* that
pipeline and caps the entire send — all retries and their back-off included — so a
10s value would abort the pipeline mid-retry and surface a bare `TaskCanceledException`
instead of the resilience layer's own timeout. Microsoft's guidance is to leave
`HttpClient.Timeout` unset (or `Timeout.InfiniteTimeSpan`) when the resilience handler
governs timing.

**Follow-up:** `YahooFinanceOptions.RequestTimeout` is currently unused as a result.
Either bind it into `AddStandardResilienceHandler(o => ...)` or delete the option.

### Added a test-fixture copy rule + captured a real Yahoo response

- `PrometheusStock.Tests.csproj`: added
  `<None Update="Fixtures\**\*.json" CopyToOutputDirectory="PreserveNewest" />` so
  fixture JSON is copied next to the test assembly and can be read at runtime.
- `backend/tests/PrometheusStock.Tests/Fixtures/yahoo-chart-5d.json`: a real response
  captured from `query1.finance.yahoo.com/v8/finance/chart/TSLA?interval=15m&range=5d`,

  (not `1mo`) to keep the file small and aggregation assertions hand-checkable.
